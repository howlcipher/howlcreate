# Providers, budgets and typed handoffs

## Provider policy

Default `auto` is the authored deterministic fixture: no discovery, network or
local model execution. Explicit unknown names fail with exit 2. Remote requests
require an explicit provider. `--provider openai` uses OPENAI_BASE_URL or
OPENAI_API_BASE and OPENAI_API_KEY. HTTPS, no redirects/proxies, and public DNS
destinations are required without local opt-in.

Local use requires `--allow-local` (Python callers use `allow_local=True`).
`HOWL_FORBID_LOCAL_INFERENCE=1` overrides permission, including cached adapters.
Never use local opt-in when this variable is set. Policy and transport are owned
by [howl-provider-core](https://github.com/howlcipher/howl-provider-core).

Remote command use requires an explicitly reviewed operator JSON profile:

```bash
HOWL_FORBID_LOCAL_INFERENCE=1 howlcreate explore "YOUR OBJECTIVE" \
  --provider command --command-config /operator/reviewed_remote.json --max-calls 16
```

The profile has argv array, remote=true, optional env_allowlist variable names,
timeout_seconds (default 120), and max_output_bytes (default 2 MiB per stream).
Prompts use stdin. No shell interpolation. Commands run in a private temporary cwd;
HOME authentication is available, but credential environment variables must be
explicitly allowed. Audit the executable's tools, hooks and local fallback first.
Profiles are never loaded from candidate artifacts or discovered automatically.
The remote declaration is not proof of an arbitrary executable's behavior.
See provider-core for its optional neutral JSON response and POSIX limitation.

`--fallback openai deterministic` explicitly authorizes these later providers.
Every dispatched attempt shares the call budget. Configuration errors fail before
execution; fallback does not reinterpret unknown names or invalid profiles.
With no fallback configured, provider failure returns PARTIAL, never another model.
An exhausted configured chain fails clearly. Requested/selected/actual provider,
requested/reported model, adapter, fixture flags, fallback reason and available
usage are persisted per response. Unreported usage and costs remain unknown.

## Exploration limits and scoring

Default `--max-calls 32` bounds generation and evaluation attempts, including
failed attempts and fallback. Zero dispatches nothing. Exhaustion saves completed
ideas and evaluations, returns exit 1, and reports BUDGET_EXHAUSTED. It does not
switch providers. Evaluation uses batches of up to eight, retaining candidate IDs.
Malformed or incomplete evaluations never receive fabricated baseline scores.

Creative branches use the supplied problem as their domain. Universal structural,
stakeholder, analogy and constraint lenses still permit cross-domain proposals.
Deterministic mode is an authored fixture, not an empirical quality evaluation.
Its operation dispatch is explicit, so words in the user's objective cannot
select a different fixture operation.

`strategic_fit` means fit to the supplied objective and constraints.
`--ecosystem-fit-weight 0.1` explicitly opts into ecosystem relevance; its default
weight is zero. Neither fixture scores nor model scores constitute verified facts.

## Typed interchange

```bash
howlcreate export RUN_OR_JSON --target dream --candidate-id IDEA_ID --output candidate.json
howldream review candidate.json --evidence supplied_ledger.json
howldream export DREAM_RUN_DIR --candidate-id DREAM_CANDIDATE_ID --format howl.candidate/v1
```

Create exports one `howl.candidate/v1` retaining the original ID, source Idea,
parents, graph, rationale, assumptions, provider execution and timestamp in
provenance. Speculations and constraints are not upgraded into evidence. Dream
review retains the entire original candidate and adds scoped review results.
For model-driven Dream challenge, put the candidate in an exploration request's
`source_candidates`; it becomes unverified context, never the evidence ledger.

Schemas are generated by Dream and vendored here; SOURCE.md records their pin.
Validation proves shape, not authenticity. Producers may be operator, adapter,
fixture, Dream, Create, or Frame. Missing producer identity remains unknown.
Legacy `howldream.handoff/v1` is not a candidate: export from its source run.

## Develop migration

`scaffold CANDIDATE --assessment ASSESSMENT` creates a candidate-specific,
non-model scaffold. `develop` now requires an explicit model provider:

```bash
howlcreate develop candidate.json --assessment assessment.json --provider command \
  --command-config /operator/reviewed_remote.json --max-calls 1 --output design.json
```

Both validate canonical schemas, matching candidate IDs, advisory authority and
ACCEPT_FOR_DEVELOPMENT. The supplied assessment is recorded verbatim; no fixed
HowlFrame attribution occurs. Source claims, evidence, uncertainty and lineage
remain attached. Development proposes design/tests; it executes nothing and
never reports tests as passed. Mock/deterministic providers cannot satisfy develop.

Python `develop_candidate(candidate, assessment)` temporarily warns and delegates
to `scaffold_candidate`. New callers should select one explicitly. Legacy assessment
extras such as reason/explanation belong in provenance or limitations; do not
invent a producing component when migrating. Existing Plane legacy evaluator
payloads need explicit adaptation before strict Create ingestion; this release
does not repair or certify that separate orchestrator's entire loop.
